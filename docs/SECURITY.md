# 安全部署说明

## 1. USB/IP 数据面不是公网 API

标准 USB/IP 设计目标是把远端 USB 总线事务转发到本地，并不等同于带身份认证的互联网业务协议。

MyUsbIP v1.0 保持标准 USB/IP 互操作性，不在 3240 数据包中加入私有认证字段，否则会破坏 Linux、usbipd-win、usbip-win 等现有实现之间的兼容性。

## 2. 推荐网络模型

生产环境建议采用以下任一方式限制 TCP 3240：

- 同一可信局域网。
- VLAN + 防火墙 ACL。
- WireGuard。
- Tailscale。
- ZeroTier。
- IPSec/企业 VPN。
- 点对点专线。

服务端只允许明确的客户端网段访问 3240。

## 3. 权限

USB 设备共享、驱动绑定和 VHCI 挂载通常需要管理员/root 权限。

不要把任意用户输入直接拼接成 shell 命令。MyUsbIP 当前 Backend 对 BusId/Host 进行参数边界封装，但业务层仍应限制允许操作的设备范围。

## 4. UKey/智能卡

UKey 往往承载证书和签名能力。建议业务系统在 MyUsbIP 上层增加：

- 用户/角色授权。
- 设备白名单。
- 用户到设备的一对一或多对一授权关系。
- 使用时间窗口。
- 单设备独占租约。
- 操作审计。
- 连接来源 IP/机器标识记录。

不要因为设备已经能够通过 USB/IP 访问，就默认所有网络客户端都有权使用该设备。

## 5. 日志隐私

诊断日志默认记录 BusId、VID/PID、Host、操作结果和错误信息。业务层如果额外记录序列号、证书主题、用户名称等信息，应根据实际合规要求设置日志保留周期和访问权限。

## 6. 后续控制面

推荐在生产业务中增加独立 HTTPS 控制面：

```text
客户端 -> HTTPS 鉴权/申请设备 -> 服务端授权 -> 放行/建立 USB/IP 数据连接
```

控制面负责身份认证、设备租约和审计，标准 USB/IP 3240 只负责数据传输。
